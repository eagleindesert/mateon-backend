## 🆕 v6-3 → v7 변경 요약

이번 개정에서는 **타인(공개) 프로필 조회 API 신설**과 **활동 북마크(즐겨찾기) 기능 도입 및 활동 응답 `bookmarked` 반영** 변경 사항이 추가되었습니다.

* **🆕 공개 프로필(타인 프로필) 조회 API 추가**: `GET /api/users/{userId}`
  - 추천 목록, 팀원 지원자 목록, 역제안 대상, DM 등에서 상대방의 상세 정보를 조회할 수 있는 공개 프로필 조회 API가 추가되었습니다.
  - 로그인한 사용자 누구나 호출 가능하나, 개인정보 보호 및 이메일 수집 방지를 위해 연락처 필드(`email`, `schoolEmail`, `providerId`)는 절대 포함하지 않습니다.
  - 기본 사용자 정보(이름, 학교, 학과, 학년, 태그라인 등)와 매칭 의도 슬롯(희망 역할, 보유 기술, 경험 수준, 활동 스타일), 협업 온도(`collaborationTemperature`, 평가 2건 미만 시 `null` 비공개), 참여 활동 이력(`participatedActivities`), 조회자 본인 여부(`isMe`)를 포함합니다.
  - `/me`, `/mypage` 등의 리터럴 경로와 충돌을 방지하기 위해 `{userId:\d+}` 숫자 정규식 제약이 적용되었습니다.
  - 존재하지 않는 사용자 ID 조회 시 기존 400 Bad Request 대신 `404 Not Found` (`USER_NOT_FOUND`) 응답으로 전환되었습니다.
* **🆕 활동 북마크(즐겨찾기) API 4종 추가**: `/api/bookmarks/events/**`
  - 활동 조회 경로(`/api/events/**`)의 비로그인 허용(permitAll) 규칙과 보안 설정을 명확히 분리하기 위해 전용 접두사 `/api/bookmarks/`를 사용하며, 모든 경로는 **인증 필수(✅)**입니다.
  - `POST /api/bookmarks/events/{eventId}`: 북마크 등록 (신규 추가 시 201 Created, 이미 추가된 상태여도 200 OK — 멱등 응답).
  - `DELETE /api/bookmarks/events/{eventId}`: 북마크 해제 (미등록 상태여도 200 OK — 멱등 응답).
  - `GET /api/bookmarks/events`: 내가 북마크한 활동 목록 조회 (북마크 등록 최신순 정렬, 오프셋 페이지네이션 `page`, `size` 지원).
  - `GET /api/bookmarks/events/ids`: 내가 찜한 활동 ID 전량 조회 (`List<Long>`, 화면별 별 아이콘 표시 대조표용).
* **🆕 활동 조회 응답 DTO (`EventResponseDTO`)에 `bookmarked` 필드 추가**:
  - `GET /api/events/search`, `POST /api/events`, `GET /api/events`, `GET /api/bookmarks/events` 등 활동 응답 객체에 `bookmarked` (`boolean`) 필드가 새로 추가되었습니다.
  - 로그인 사용자 본인이 해당 활동을 북마크했는지 여부를 나타내며, 비로그인 상태 조회 시 항상 `false`를 반환합니다.
* **🆕 PostgreSQL `event_bookmarks` 테이블 도입 (V24 마이그레이션)**:
  - `event_bookmarks` 테이블(`id`, `user_id`, `event_id`, `created_at`)이 추가되었습니다.
  - 사용자/활동 외래키 `ON DELETE CASCADE` 지정, 중복 방지를 위한 `(user_id, event_id)` 유니크 제약 `uq_event_bookmarks_pair` 및 최신순 조회를 위한 `(user_id, created_at DESC)` 인덱스가 구축되었습니다.

## 1. 인증 (Auth)

### POST `/api/auth/email/request` — 이메일 인증코드 발송

* **인증 요구사항**: ❌
* **설명**: 회원가입용 이메일 인증 코드를 전송합니다. 메일 남용 방지를 위한 60초의 재요청 제한(쿨다운)이 적용됩니다.

**Request Body (`EmailRequest`)**

| 필드 | 타입 | 필수 | Validation | 설명 |
|---|---|---|---|---|
| email | String | ✅ | @NotBlank, @Email | 인증코드를 받을 이메일 |

**Response 200 OK**

| 필드 | 타입 | 설명 |
|---|---|---|
| success | Boolean | 성공 여부 (`true`) |
| message | String | 결과 메시지 (`인증코드가 발송되었습니다.`) |
| data | Object | `null` |

**예외 응답**
* **429 Too Many Requests**: 60초 이내에 동일 이메일로 다시 요청하는 경우 (`EMAIL_REQUEST_TOO_FREQUENT`)

---

### POST `/api/auth/email/verify` — 이메일 인증코드 검증

* **인증 요구사항**: ❌
* **설명**: 이메일로 발급된 6자리 인증코드를 확인하고, 검증 성공 시 회원가입 API(`/signup`)에 반드시 동반해야 하는 일회용 티켓(`verificationToken`)을 반환합니다.

**Request Body (`EmailVerifyRequest`)**

| 필드 | 타입 | 필수 | Validation | 설명 |
|---|---|---|---|---|
| email | String | ✅ | @NotBlank, @Email | 검증할 사용자 이메일 |
| code | String | ✅ | @NotBlank, @Pattern("^\\d{6}$") | 이메일로 받은 6자리 인증코드 |

**Response 200 OK**

| 필드 | 타입 | 설명 |
|---|---|---|
| success | Boolean | 성공 여부 (`true`) |
| message | String | 결과 메시지 (`이메일 인증이 완료되었습니다.`) |
| data | Object | 인증 성공 응답 데이터 |
| data.verificationToken | String | 회원가입 시 주체 인증용으로 제출할 일회용 티켓 |

**예외 응답**
* **400 Bad Request**: 인증코드가 일치하지 않거나 만료된 경우 (`INVALID_VERIFICATION_CODE`)

### POST `/api/auth/school/email/request` — 학교 이메일 인증코드 발송

* **인증 요구사항**: ✅ (로그인 상태)
* **설명**: 로그인한 사용자의 재학생(학교) 인증을 위해 학교 메일로 인증코드를 보냅니다. 60초의 재요청 제한(쿨다운)이 적용됩니다.

**Headers**

| 헤더 | 값 | 필수 |
|---|---|---|
| Authorization | Bearer {accessToken} | ✅ |

**Request Body (`SchoolEmailRequest`)**

| 필드 | 타입 | 필수 | Validation | 설명 |
|---|---|---|---|---|
| schoolEmail | String | ✅ | @NotBlank, @Email | 학교(재학생) 이메일 주소 |

**Response 200 OK**

| 필드 | 타입 | 설명 |
|---|---|---|
| success | Boolean | 성공 여부 (`true`) |
| message | String | 결과 메시지 (`학교 이메일로 인증코드가 발송되었습니다.`) |
| data | Object | `null` |

**예외 응답**
* **429 Too Many Requests**: 60초 이내에 동일 이메일로 다시 요청하는 경우 (`EMAIL_REQUEST_TOO_FREQUENT`)

### GET `/api/events/search` — 활동 검색

* **설명**: 필터(자유 검색어 키워드/대학교/단과대/카테고리/분야)는 모두 선택이며 자유롭게 조합할 수 있습니다. 결과는 항상 활동 시작일(`startDate`) 최신순이며(같으면 id 내림차순), **로그인 여부와 무관하게 순서가 같습니다.**
* **자유 키워드 검색**: `keyword` 파라미터를 제공하여 제목(`title`), 상세 설명(`description`), 주최/주관(`organizer`) 세 컬럼을 대상으로 하는 부분일치(OR 조건) 키워드 검색을 지원하며, 기존 필터 조건들과는 `AND` 조건으로 결합됩니다.

* 🆕 **북마크 여부 반영**: 응답 개별 항목의 `bookmarked` 필드에 로그인한 사용자의 북마크 여부가 반영됩니다 (비로그인 상태 조회 시 항상 `false`).
